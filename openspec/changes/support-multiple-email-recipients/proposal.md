# 支持 NAS 邮件脚本发送给多个收件人

## 摘要

修改 NAS 邮件发送脚本，让 `MAIL_TO` 可以配置多个邮箱地址，并由脚本稳定地逐个发送每日股票日报或失败日志。

## 背景与动机

当前 `scripts/nas_update_and_mail.sh` 将 `MAIL_TO` 作为一个整体参数传给 `mail`：

```bash
"$MAIL_BIN" -s "$subject" "$MAIL_TO" < "$BODY_FILE"
```

这对单个邮箱可用，但当 `MAIL_TO="a@example.com b@example.com"` 时，不同 NAS 上的 `mail` 实现可能把它当成一个非法收件人，而不是两个收件人。用户现在希望同一份日报可以发给多人，并且后续 cron 只需要配置一处收件人列表。

## 范围

本次包含：

- 让 `MAIL_TO` 支持逗号、空格、分号分隔的多个邮箱。
- 脚本内部解析收件人列表，过滤空白项。
- 成功日报和失败日志都按同一收件人列表逐个发送。
- 任一收件人发送失败时，脚本应记录失败地址并返回非零状态。
- 更新 NAS 部署文档中的 cron 示例，说明多人邮箱写法。
- 增加 shell 级别测试或等价验证，覆盖单人、多人、空收件人和发送失败行为。

本次不包含：

- 修改邮件正文生成逻辑。
- 修改 `docker compose run --rm update-report` 的数据更新流程。
- 引入新的邮件服务商、SMTP 配置管理或联系人管理功能。
- 改变工作日 17:00 更新、工作日 09:00 发送的 cron 策略。

## 成功标准

- `MAIL_TO="a@example.com,b@example.com"` 可以向两个地址发送。
- `MAIL_TO="a@example.com b@example.com"` 也可以向两个地址发送。
- `MAIL_TO="a@example.com;b@example.com"` 也可以向两个地址发送。
- 未配置有效收件人时，脚本明确报错并退出状态 `2`。
- 如果多个收件人中有任意一个发送失败，脚本最终退出非零并在日志中写明失败地址。
- 单个收件人的既有用法保持兼容。
- 文档给出多人收件人的推荐 cron 示例。
