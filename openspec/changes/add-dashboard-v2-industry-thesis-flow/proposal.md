# 增加 dashboardv2 行业主线选股模式

## 摘要

在保留现有 `dashboard` 交互不变的前提下，新增一个 `dashboardv2` 入口，改用“行业主线 -> 主线股票池 -> 龙头收敛 -> 技术确认 -> 每日复盘”的选股链路。v2 重点解决当前 dashboard 黑盒感重、技术面过强、候选股过多导致不敢买的问题。

## 背景与动机

当前 dashboard 主要以 CSI 300 为基础池，从宏观粗筛到技术分析再到操作建议，适合做研究排序，但用户仍会感觉：

- 选出来的股票像短线机会，需要频繁盯盘；
- 技术面信息偏多，主导感强；
- 即使有分数，也不清楚为什么是这几只股票；
- 候选数量太大，不利于建立少量、可持续复盘的决策节奏。

用户希望改成更容易理解的链路：

1. 获取某个行业近一个月指数涨幅。
2. 解释行业上涨的具体原因。
3. 选出行业龙头股。
4. 再做技术面分析。

因此需要一个保留现有 dashboard、但增加行业主线版本的双轨交互。

## 范围

本次包含：

- 保留当前 `dashboard` 版本与现有交互。
- 新增 `dashboardv2` 入口，展示行业主线链路。
- 复用现有 SQLite 缓存、财报、行情、成分股和技术分析数据。
- 增加行业主线层的数据接入与解释层。
- 将高潜力与好时机的既有分析结果重定位为“龙头收敛”和“技术确认”。
- 将每日复盘限定为少数主线行业和少数龙头股票。

本次不包含：

- 删除或重写现有 `dashboard` 交互。
- 新增实时荐股、自动交易或仓位建议。
- 改变现有技术指标公式或宏观粗筛公式。
- 强制用户放弃 CSI 300 基础池。

## 成功标准

- 用户可以同时使用 `dashboard` v1 和 `dashboardv2`，两者互不覆盖。
- v2 首页能清晰表达“行业主线 -> 龙头 -> 技术确认”的层级。
- v2 只需要每日复盘少数主线和少数龙头，而不是全市场或大量短线候选。
- v2 能复用现有缓存与数据表，新增的数据抓取量尽量最小。
- v2 的解释层能让用户看懂“为什么这个行业在涨、为什么是这几只股票、为什么现在能/不能下手”。
