# 设计

## 概览

`dashboardv2` 是与现有 dashboard 并存的第二套交互模式。它保留现有项目的数据底座与缓存机制，但改变研究心智：

```text
行业主线 -> 主线股票池 -> 龙头收敛 -> 技术确认 -> 每日复盘
```

v1 继续作为通用研究与排序视图，v2 作为少数主线股票的解释型复盘视图。两者共享数据层，但 UI、入口和快照版本隔离。

## 交互结构

### 左侧：行业主线榜

展示近一个月的行业指数涨幅、上涨家数、成交额变化和主线强度。用户先选行业，再进入下钻视图。

### 中间：主线股票池

行业选中后，展示该行业内的主线股票池。这个池不是全市场股票池，而是“CSI 300 基础池 + 行业主线过滤”的结果，必要时可以扩展到行业地位明确但不在 CSI 300 的观察股。

### 右侧：龙头证据卡 + 技术确认

右侧上半区解释为什么这些股票值得跟踪，下半区解释能不能下手。这里不再强调技术分本身，而强调：

- 结论
- 关键价位
- 趋势证据
- 量能证据
- 风险提醒

### 底部：每日复盘队列

只展示少数主线和少数龙头，默认每日跟踪 1-3 只股票。复盘动作是“继续观察、等待回踩、等待放量确认、提醒触发、放弃”。

## 数据流

### 行业层

行业主线数据优先来自现有可复用的公开 A 股数据：

- 行业板块名称与涨幅排行
- 行业板块历史走势
- 行业板块成分股
- 行业资金流和新闻/催化摘要（如可用）

这些数据主要用于解释行业为什么涨，而不是独立生成买入建议。

### 龙头层

行业成分股进入龙头收敛逻辑后，复用现有项目中的：

- 市值快照
- 财报字段
- 日线行情
- 行业内相对强弱

高潜力在 v2 里重定位为“龙头排序能力”，好时机重定位为“技术确认能力”。

### 技术层

技术分析只对少数龙头执行，并输出可读的确认结论，而不是让技术分回到主选股入口。

## 数据复用与隔离

- 复用现有 SQLite、`quotes_daily`、`financial_reports`、`industry_members`、`index_constituents` 等缓存。
- v1 和 v2 共用同一数据底座，但快照与渲染版本需要区分。
- `dashboardv2` 不改变现有 `dashboard` 的主流程、默认入口和快照语义。

## 错误处理

- 若行业板块数据不可用，v2 显示“行业层暂不可用”，但不影响 v1。
- 若某行业缺少成分股或历史涨幅数据，主线池降级为保守提示，不自动扩展成全市场筛选。
- 若行业解释数据不足，说明必须保守，不得编造上涨原因。

## 测试

需要覆盖：

- v1 dashboard 仍能正常生成。
- v2 能展示行业主线榜、主线股票池、龙头证据卡、技术确认和每日复盘。
- v2 的数据复用逻辑不会破坏现有缓存。
- v2 不会把大量技术分析结果重新拉回主入口。
- v2 缺少行业数据时的降级行为保守且可解释。
