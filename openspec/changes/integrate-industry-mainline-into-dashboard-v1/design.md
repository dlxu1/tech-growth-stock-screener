# 设计

## 概览

本次变更把行业主线从独立 `dashboardv2` 迁入现有 `dashboard` v1。v1 的主流程从用户感知上调整为：

```text
数据健康 -> 行业主线证据 -> 行业股票池 -> 宏观粗筛/高潜力 -> 技术分析/好时机 -> 操作建议/复盘
```

底层仍然保留现有串行阶段约束：下游阶段只能消费上游阶段产生的候选股。本次不是把行业卡片做成纯前端展示，而是让选中行业成为 dashboard 计算参数或等价的数据作用域，确保下面的高潜力和好时机结果真的来自该行业股票池。

## 交互结构

### 1. 数据健康

保留现有 v1 数据健康条，继续展示健康分、最新行情日、缺指标数量、操作建议可执行数、阶段串行状态、策略口径和权重版本。

### 2. 行业主线证据板

新增模块位于数据健康条下方。模块展示：

- 行业主线榜：行业名称、排名、近 1 个月或可用窗口涨幅、上涨家数占比、成交额变化、主线强度。
- 证据拆解：价格扩散、量能承接、成长样本、回撤风险、数据完整性。
- 行业股票池说明：当前选中行业下可进入后续分析的股票数量、数据来源和缺失提示。
- 默认选择：页面初始选中行业主线排名第一的行业。

行业榜点击后有两种可接受实现：

- 首期推荐：点击行业通过 URL 参数重新加载 dashboard，例如 `industry=<board_name>` 或复用更明确的 `sector=<board_name>` 参数，使后续阶段按该行业重算。
- 后续增强：在服务器端预计算 Top N 行业的完整下游结果，实现无刷新切换。

首期推荐服务端重算，因为它能保证矩阵、高潜力、好时机和操作建议的数据范围真实一致。

### 3. 高潜力与好时机模块

保留现有 v1 的成熟交互，包括：

- `宏观潜力 × 技术时机` 矩阵。
- 右侧股票详情。
- 高潜力+好时机判断。
- 操作建议、数据回测、操作回测、信号验证与预警等现有模块。

变化是候选范围：这些模块默认消费选中行业股票池，而不是沪深 300 全池。页面文案需要明确显示当前股票池来源，例如：

```text
当前股票池：半导体行业成分股 87 只；进入宏观粗筛 87 只；进入技术分析 87 只。
```

若当前只能拿到沪深 300 内的行业样本，则必须写成：

```text
当前股票池：沪深 300 中的半导体样本 18 只；行业全成分股暂不可用。
```

## 数据流

### 行业主线计算

首期复用 `dashboardv2` 已有的行业主线对象构造能力，但需要将其从 v2 renderer 中抽出到 dashboard 可复用层，避免 v1 依赖 v2 页面文件。

排序公式可以直接复用当前 v2 的证据排序骨架：按 `board_name` 分组后，继续结合涨幅、上涨家数占比、成交额、成长样本和回撤风险生成主线强度分数。变化点不在公式本身，而在输入池和口径标注：

- 输入池优先切换为当前选中行业的股票池。
- 若只有缓存样本，则标注为样本代理口径。
- 若已覆盖行业全成分股，则标注为行业成分股口径。

行业主线榜首期可以继续使用缓存可得字段估算：

- `board_name`
- 行业样本数量
- 近期涨幅，如 `return_60d` 或可替代窗口
- 上涨家数占比
- `amount_20d`
- `revenue_yoy`
- `profit_yoy`
- `max_drawdown_252d`

展示中必须标注这是“缓存样本估算”或“行业全成分股统计”，取决于实际数据来源。

### 行业股票池

选中行业应成为后续串行阶段的上游股票池。实现时需要区分两种数据覆盖：

1. 行业全成分股可用：从 `industry_members` 或等价缓存读取选中行业所有成分股，再合并财报、行情、市值和行业字段。
2. 行业全成分股不可用：降级为当前基础池中的行业样本，例如沪深 300 中 `board_name` 命中的股票，并在页面清晰提示。

不允许在行业成分股缺失时自动退回全市场黑盒筛选。

### 串行阶段

下游阶段继续沿用现有顺序：

```text
股票池 -> 宏观粗筛 -> 技术分析 -> 操作建议
```

但本次要求 `股票池` 的业务含义从“默认沪深 300 全池”变成“选中行业的股票池”。因此：

- `sector_screen` 或等价上游阶段应输出选中行业股票池。
- `combo` 只能消费该行业股票池。
- `fine` 只能消费 `combo` 结果。
- `plan` 只能消费 `fine` 的高关注结果。

### dashboardv2 暂停更新

`dashboardv2` 不再作为新需求的主要承载页。可保留已有命令和路由以避免破坏历史链接，但后续功能、文案和交互更新集中到 `dashboard` v1。

若需要更强约束，可在实施阶段选择：

- 保留 `/dashboardv2`，展示“此入口已暂停更新，请使用 dashboard 主入口”的提示。
- 或保留现有 v2 静态能力但不再新增功能，并在文档中标记为 deprecated。

首期建议保留兼容入口，避免突然删除已有链接。

## 错误处理与降级

- 行业主线无数据：隐藏行业证据板主体或展示“暂无行业主线数据”，下方模块继续按原有 dashboard 参数运行，但必须标注未应用行业过滤。
- 默认第一行业无可用成分股：选择下一条有成分股的行业；若全部不可用，则降级为当前基础池样本并提示。
- 行业解释数据不足：只展示量化证据，不编造上涨原因。
- 行业股票池日线缺失较多：数据健康栏和行业证据板同时提示缺失数量，后续技术分析按现有缺失处理规则保守输出。

## 测试

需要新增或更新测试覆盖：

- v1 HTML 中行业证据板出现在数据健康条之后、矩阵模块之前。
- 默认选中行业主线排名第一的行业。
- dashboard-server 能通过请求参数传递选中行业，并触发同一行业下游重算。
- 下游阶段候选股均来自选中行业股票池，继续满足串行关系。
- 行业全成分股不可用时，页面显示缓存样本/指数内样本降级说明。
- `dashboardv2` 不再作为新增交互的测试重点，但兼容入口不应导致现有测试失败。

## 待确认点

- “行业的所有股票”在实施时优先解释为行业板块全成分股；若本地缓存暂不完整，则先明确降级为缓存样本。
- 行业切换首期采用服务端重算，不做纯前端假切换。
- 是否将 `dashboardv2` 页面显示为 deprecated 提示，还是仅文档标记暂停更新，实施前由用户 review 决定。
