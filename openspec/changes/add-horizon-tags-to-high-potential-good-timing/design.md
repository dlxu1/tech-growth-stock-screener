# 设计

## 概览

在 dashboard 合并宏观、技术和操作计划行之后，增加一个轻量的投资周期分类层。分类器读取现有字段，并输出仅用于展示的注释字段：

- `horizon_tags`: 按固定顺序排列的 `长线`, `中线`, `短线`
- `primary_horizon`: 根据证据强度选出的优先关注周期
- `horizon_reason`: 面向 UI 的简短中文解释
- `horizon_data_note`: 数据完整性和保守提示

分类器不得改变阶段成员、评分、阈值、排序、操作建议或回测样本。

## 分类规则

只有被归类为 `高潜力 + 好时机` 的行，才在矩阵中突出展示投资周期标记。其他行可以携带计算字段，便于调试或后续过滤，但 UI 应重点强调目标象限内的标记。

### 长线标记

当股票具备较强的长期基本面证据时，使用 `长线`：

- `quality_score >= 75`
- `risk_control_score >= 65`
- `growth_score >= 60`
- 至少命中一个价值、质量或成长类策略，例如：
  - `高 ROE + 合理估值`
  - `高毛利率 + 营收增长`
  - `市值前排 + 营收净利双增长`
  - `低 PE + 正增长`
  - `低 PB + 正盈利`
  - `回撤较小 + 正增长`

不能只因为 `technical_score` 较高或命中 `price_strength_market_cap`，就授予 `长线` 标记。

### 中线标记

当宏观潜力和趋势时机同时可用时，使用 `中线`：

- `combo_score >= 80`
- `technical_score >= 75`

当长线或短线证据都不占主导时，`中线` 是强矩阵候选股的默认标记。

### 短线标记

只有当操作计划在现有规则下可执行时，才使用 `短线`：

- `usable_for_plan == true`
- `primary_strategy` 是以下值之一：
  - `breakout_buy`
  - `pullback_ma_buy`
  - `volume_confirm_buy`
- `planned_entry` 和 `initial_stop` 是有效正数。
- `risk_pct` 存在且满足 `0 < risk_pct <= 0.12`。

短线标记描述的是下一交易日执行条件，不是泛化的持有周期建议。

## 数据流

1. Dashboard pipeline 运行现有串行阶段。
2. View-model 层合并股票池、宏观、技术和操作计划行。
3. 投资周期分类器读取合并后的行并返回注释字段。
4. Dashboard JSON 在矩阵、详情和表格行中包含这些字段。
5. HTML 渲染器在以下位置展示紧凑标签：
   - 顶部数据健康栏展示 `策略口径`、`权重版本` 等全局状态
   - 矩阵选中股票详情面板
   - 操作建议表
   - 有助于检索和解释的矩阵 hover/search 文本
6. 每日邮件摘要生成器读取同一批字段，在 `好时机+高潜力` 个股明细中输出周期信息。

## UI 行为

顶部数据健康栏展示本次 dashboard 的全局状态，不展示个股周期标签：

```text
数据健康：100/100
市场研判：震荡
策略口径：潜力股组合评分
权重版本：震荡防御版
```

`权重版本` 必须支持鼠标悬停说明，解释当前版本为何这样加权：

- `牛市动量版`: 更重视动量和价格强势。
- `震荡防御版`: 更重视质量、风控、反转，弱化动量。
- `熊市防御版`: 质量和风控权重最高，动量不参与总分。

悬停文案应使用当前实际版本对应的一条说明；如果需要展示完整规则，可在 tooltip 中追加 `由市场状态投票自动切换`。

选中股票详情面板应在股票名称或状态附近展示个股周期标记：

```text
适合周期：长线 / 中线 / 短线
优先关注：中线
```

示例：

- `长线 + 中线`: 基本面质量较强，同时当前技术窗口可观察。
- `中线 + 短线`: 宏观潜力和技术时机共振，且已有可执行入场/止损计划。
- `短线`: 仅代表操作计划可执行，不代表长期价值确认。

如果没有分配标记，展示弱化说明，例如：

```text
适合周期：证据不足，需人工复核
```

## 邮件摘要行为

每日邮件摘要应继续使用现有 `好时机+高潜力` 选股逻辑，不新增独立筛选。每只候选股在已有字段后补充：

```text
适合周期：长线 / 中线
优先关注：中线
周期说明：质量分高、回撤可控，且宏观潜力与技术时机共振。
```

邮件正文和 JSON payload 都应包含以下字段：

- `horizon_tags`
- `primary_horizon`
- `horizon_reason`
- `horizon_data_note`

如果数据不足，邮件中应展示：

```text
适合周期：证据不足，需人工复核
```

邮件风险提示保持不变，仍说明内容仅用于研究和辅助决策，不构成投资建议。

## 错误处理与数据缺口

- 缺少宏观或技术分时，应抑制标记并设置 `horizon_data_note`。
- 缺少策略命中详情时，仍可允许基于分数的 `中线` 标记，但不允许触发依赖具体策略证据的 `长线` 标记。
- 缺少 `planned_entry` 或 `initial_stop` 时，必须抑制 `短线` 标记。
- 邮件摘要读取不到周期字段时，不得重新发明另一套规则；应使用 `证据不足，需人工复核` 或沿用 dashboard model 中的保守说明。
- 所有标签文案必须保持保守，不得包含配置、预算或仓位字段。

## 测试

新增测试覆盖：

- 质量、价值、成长证据触发长线标记。
- `高潜力 + 好时机` 触发中线标记。
- 只有操作计划字段可执行时才触发短线标记。
- 多标签行保持确定顺序：`长线`, `中线`, `短线`。
- 数据缺失时不强制打标，并返回数据说明。
- Dashboard HTML 能渲染周期标签，且不改变阶段数量或阈值。
- 每日邮件摘要正文和 payload 均包含个股周期字段。
